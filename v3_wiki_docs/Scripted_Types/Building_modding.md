# Building modding

From Victoria 3 Wiki

[Jump to navigation](#mw-head) [Jump to search](#searchInput)

[Buildings](/Buildings "Buildings") are one of the foundational pillars of Victoria 3. Thus plenty of mods will want to add new buildings to the game. Further, [production methods](/Production_method "Production method") are integral to the functioning of a building, and as such this page also contains an explanation on how to mod those.

## Building groups\[[edit](/index.php?title=Building_modding&veaction=edit&section=1 "Edit section: Building groups") | [edit source](/index.php?title=Building_modding&action=edit&section=1 "Edit section: Building groups")\]

Each building belongs to a *building group*. Building groups are defined in /Victoria 3/game/common/building\_groups and follow the following basic format:

\[building\_group\]= {
	category = \[urban/rural/development\]
	
	economy\_of\_scale = \[yes/no\]
	
	cash\_reserves\_max = \[integer\]
	
	should\_auto\_expand = { 
		\[trigger\]
	}
	
	economy\_of\_scale\_ai\_factor = \[float\]
}

Each building group needs its own unique script name; by convention this is `bg_[script_name]`. Building groups can also have parent groups, from which they inherit and can also overwrite characteristics. So for example:

bg\_manufacturing = {
	category = urban

	always\_possible = yes
	
	economy\_of\_scale = yes
	
	cash\_reserves\_max = 25000
	
	should\_auto\_expand = { 
		default\_auto\_expand\_rule = yes
	}
	
	economy\_of\_scale\_ai\_factor = 4.0
}

bg\_light\_industry = {
	parent\_group = bg\_manufacturing

	lens = light\_industry
	
	urbanization = 20
	infrastructure\_usage\_per\_level = 2
}

Child groups inherit all values from their parents, but can also define more characteristics themselves and will overwrite their parents' characteristics. Buildings themselves can further overwrite even their category values.

### Resource caps and farm types\[[edit](/index.php?title=Building_modding&veaction=edit&section=2 "Edit section: Resource caps and farm types") | [edit source](/index.php?title=Building_modding&action=edit&section=2 "Edit section: Resource caps and farm types")\]

Limited buildings are often capped based on [state region definitions](/State_modding "State modding"). As an example:

STATE\_CALIFORNIA = {
    id = 326
    subsistence\_building = "building\_subsistence\_farms"
    provinces = { list of provinces }
    traits = { "state\_trait\_central\_valley" "state\_trait\_northern\_california\_coastal\_forests" }
    city = "x5EF8F5"
    port = "x1116AA"
    farm = "x7A5DA6"
    mine = "x4C2D30"
    wood = "x607BA8"
    arable\_land = 300
    arable\_resources = { "bg\_wheat\_farms" "bg\_livestock\_ranches" "bg\_cotton\_plantations" "bg\_vineyard\_plantations" }
    capped\_resources = {
        bg\_iron\_mining = 33
        bg\_sulfur\_mining = 40
        bg\_logging = 13
        bg\_fishing = 14
    }
    resource = {
        type = "bg\_gold\_fields"
        depleted\_type = "bg\_gold\_mining"
        undiscovered\_amount = 12
    }
    resource = {
        type = "bg\_oil\_extraction"
        undiscovered\_amount = 50
    }
    naval\_exit\_id = 3153
}

The following state characteristics are relevant for buildings

subsistence\_building

Which building will be used for the default subsistence type, must be something defined as a subsistence building.

arable\_land

This sets how much arable land there is available in the state. Every building group with `land_usage = rural` uses and shares this cap.

arable\_resources

The list of building groups that can be built with this state's arable land.

capped\_resources

How many buildings of each of these building groups can be built, used when the group uses `capped_by_resources = yes`.

undiscovered\_amount

This is just like the other type of resource cap, however it is not immediately visible to the player and requires both tech and some time to be revealed. Building group needs to have `` discoverable_resource = yes`.` ``

discovered\_amount

Like undiscovered\_amount, but discovered. Basically, how many buildings of this group can be built from game start, but for a building group that has `` discoverable_resource = yes`.` ``

depleted\_type

For building groups with `depletable_resource = yes`. Once this resource is depleted in this state (based on various random rolls defined in [Defines](/Defines#Economy "Defines") or through the `force_resource_depletion` effect), replaces and deletes buildings of the initial group with the second group, with amount as new cap.

While they are mostly self-explanatory, a lot of the very specifics of discovery and depletion are still hidden in the game. Here is some additional info for context, some of it coming from testing.\[But more testing or information is needed\]

As soon as a nation has discovers a technology that allows the building of a building whose building group uses `discoverable_resource = yes`, the game will start rolling discovery of that resource for each state of that nation with still some "undiscovered building\_groups" left. That roll is happening every day, and uses the `BASE_RESOURCE_DISCOVER_CHANCE` value, which by default means a 0.02% chance per day per state. If the roll is successful, between 20% to 50% of all remaining `undiscovered_amount` will be available to be build. Further, every other nation with a declared interest in that state gets a notification.

There are also some events related to discovery, that use the command `force_resource_discovery`. For example, after a nation researches [![Pumpjacks](/images/thumb/6/65/Invention_pumpjacks.png/24px-Invention_pumpjacks.png)](/Production_technology#Pumpjacks "Pumpjacks") Pumpjacks, that nation automatically gets a free and instant discovery of oil in one of its states. Similarly, the (relatively common) Rubber event forces rubber discovery in your state or an adjacent state.

If the building group has `depletable_resource = yes`, the game will roll for depletion of that building group in every state. The base chance is 0.005% per day multiplied by each fully employed level. So, if a Gold Field has 8 levels and is fully employed, that means that building group has a 0.04% chance every day to succeed at the depletion roll. If it succeeds, between 2-5 level caps of that building group will be removed and replaced with the same amount of levels of the relevant building group in that resource's `depleted_type` entry.

## Production methods\[[edit](/index.php?title=Building_modding&veaction=edit&section=5 "Edit section: Production methods") | [edit source](/index.php?title=Building_modding&action=edit&section=5 "Edit section: Production methods")\]

### Production method groups\[[edit](/index.php?title=Building_modding&veaction=edit&section=6 "Edit section: Production method groups") | [edit source](/index.php?title=Building_modding&action=edit&section=6 "Edit section: Production method groups")\]

Production method groups are sets of mutually exclusive production methods a building has access to, e.g. Bakeries, Sweeteners, Baking Powder.

Production method groups are defined in /Victoria 3/game/common/production\_method\_groups and follow the basic format below:

\[production\_method\_group\] = {
	texture = \[path\]
	production\_methods = {
		\[production\_method\]
	}
}

Each production method group needs its own unique script name; by convention this is `pmg_[script_name]`. There can be any number of production methods within a group, but only one can be active at a time.

### Production methods\[[edit](/index.php?title=Building_modding&veaction=edit&section=7 "Edit section: Production methods") | [edit source](/index.php?title=Building_modding&action=edit&section=7 "Edit section: Production methods")\]

Production methods set the input and output for buildings, and thus are highly impactful for the game. Production methods are defined in /Victoria 3/game/common/production\_methods and follow the basic format below:

\[production\_method\] = {
	texture = \[path\]
	
	building\_modifiers = {
		workforce\_scaled = {
			\[modifiers\]
		}

		level\_scaled = {
			\[modifiers\]
		}
	}
}

Each production method needs its own unique script name; by convention this is commonly `pm_[script_name]` and often includes the building name to distinguish related variants. The above is just the most common set-up, but there are many characteristics and options.

Production method effects are generally expressed through [modifiers](/Modifier_types "Modifier types"), these can apply to the country, state, or building, and can be scaled by the building level, employment percentage, or unscaled.

These modifiers are multiplied by the building level, then scaled by the employment level of the building as a percentage.

	goods\_input\_hardwood\_add = 25

	goods\_output\_furniture\_add = -55
	goods\_output\_luxury\_furniture\_add = 55
}

These modifiers are multiplied by the level of the building.  
Most commonly used with employment level.

[![Method precision tools.png](/images/thumb/0/0a/Method_precision_tools.png/24px-Method_precision_tools.png)](/File:Method_precision_tools.png) Furniture Industry's Precision Tools

}
