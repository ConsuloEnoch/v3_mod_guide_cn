## Goods\[[edit](/index.php?title=Goods_modding&veaction=edit&section=1 "Edit section: Goods") | [edit source](/index.php?title=Goods_modding&action=edit&section=1 "Edit section: Goods")\]

![Ambox outdated info.png](https://central.paradoxwikis.com/images/thumb/6/65/Ambox_outdated_info.png/22px-Ambox_outdated_info.png)

Please help with verifying or updating this section. It was last verified for [version](/Victoria_3_Wiki:Versioning "Victoria 3 Wiki:Versioning") 1.9.

Goods are defined in /common/goods/.

Most basic goods follow the following format:

<good> = {
	texture = <path> # GFX reference used to define equipment picture in lend-lease
	cost = <int> # The base cost
	category = staple # staple/industrial/luxury/military

	prestige\_factor = 5 # Base prestige for occupying the rank MIN\_PRESTIGE\_AWARD spot on the goods production leaderboard. x2 awarded for every rank above the minimum.
}

Further, the following characteristics can be added:

consumption\_tax\_cost = <int>

Authority cost to turn on consumption tax for this good

local = yes

Makes good local to the state, like Electricity, Services, Transportation.

tradeable = no

Disallows trading of the good. Only used for gold in vanilla.

fixed\_price = yes

Used for gold. Used to create a permanent "fake demand" set at the base price, to pay employees and dividends.

Every local good is also automatically not tradable.

While currently only gold uses both "tradable = no" and "fixed\_price = yes", there is nothing that prevents mixing various characteristics. A non-tradable good that is not local, for example, describes pre-1.5 electricity and services. A fixed\_price good could be used as an input.

### Prestige goods\[[edit](/index.php?title=Goods_modding&veaction=edit&section=2 "Edit section: Prestige goods") | [edit source](/index.php?title=Goods_modding&action=edit&section=2 "Edit section: Prestige goods")\]

Prestige goods are defined in common/prestige\_goods/. Each prestige good defines its base good and an icon. There is also a `prestige_bonus` parameter, with unclear function. For example:

prestige\_good\_krupp\_guns = {
	base\_good = artillery
	prestige\_bonus = 0.1
	texture = "gfx/interface/icons/goods\_icons/prestige\_goods/krupp\_guns\_prestige.dds"
}

Only three prestige goods can be defined for any given base good. The first three defined are used, and any later definitions are "merged" into the third definition. In unmodified Victoria 3, there is a distinction between "flavored" and "generic" prestige goods, which is driven by a mechanic that prevents immediate production of "generic" prestige goods. This is set via a [journal entry](/Journal_entry_modding "Journal entry modding") which sets a [variable](/Variable "Variable") on a given company.

## Text icon\[[edit](/index.php?title=Goods_modding&veaction=edit&section=3 "Edit section: Text icon") | [edit source](/index.php?title=Goods_modding&action=edit&section=3 "Edit section: Text icon")\]

Each good should have an icon defined in /gui/. See /Victoria 3/game/gui/goods\_texticons.gui for the base game examples.

texticon = {
	icon = <good>
	iconsize = {
		texture = <path>
		size = { 25 25 }
		offset = { 0 7 }
		fontsize = 18
	}
}

 <good>: "X"

### Building use\[[edit](/index.php?title=Goods_modding&veaction=edit&section=7 "Edit section: Building use") | [edit source](/index.php?title=Goods_modding&action=edit&section=7 "Edit section: Building use")\]

*See also: [Modifier types § Object-based modifiers](/Modifier_types#Object-based_modifiers "Modifier types")*

For a good to be produced and consumed by production methods there needs to be a modifier in /common/modifier\_type\_definitions/.

The relevant entries look like this:

goods\_input\_<good>\_add = {
	decimals=1
	color=bad
	game\_data={
		ai\_value=0
	}
}
goods\_output\_<good>\_add = {
	decimals=1
	color=good
	game\_data={
		ai\_value=0
	}
}

Multiplier modifiers can also be defined as:

goods\_input\_<good>\_mult={
	decimals=0
	color=bad
	percent=yes
	game\_data={
		ai\_value=0
	}
}
goods\_output\_<good>\_mult={
	decimals=1
	color=good
	percent=yes
	game\_data={
		ai\_value=0
	}
}

In addition, following localization needs to be added:

 modifier\_goods\_output\_<good>\_add:0 "@<good>! Videogames output per level"
 modifier\_goods\_output\_<good>\_add\_desc:0 "The amount of @<good>! Videogames produced by buildings"

 modifier\_goods\_input\_<good>\_add:0 "@<good>! Videogames input per level"
 modifier\_goods\_input\_<good>\_add\_desc:0 "The amount of @<good>! Videogames consumed by buildings"

### Pop consumption\[[edit](/index.php?title=Goods_modding&veaction=edit&section=8 "Edit section: Pop consumption") | [edit source](/index.php?title=Goods_modding&action=edit&section=8 "Edit section: Pop consumption")\]

*See also: [Needs](/Needs "Needs")*

To have pops consume the good, there needs to be an entry in /common/pop\_needs/.

#### Adding to existing need\[[edit](/index.php?title=Goods_modding&veaction=edit&section=9 "Edit section: Adding to existing need") | [edit source](/index.php?title=Goods_modding&action=edit&section=9 "Edit section: Adding to existing need")\]

Adding a good as a substitute is rather simple, using the crude items need as an example here:

\# goods						The good being referenced
# weight					The base weight that is applied to this good based on market Sell Order share
# max\_supply\_share			The maximum weight that can be applied to this good based on market Sell Order share, relative supply above this amount will have no further impact on base weight
# min\_supply\_share			If above 0, a minimum of this multiplier of the base weight will be applied to a good regardless of its market Sell Order share

popneed\_crude\_items = {
	default = wood

	entry = {
		goods = wood
		
		weight = 1
		max\_supply\_share = 0.5
		min\_supply\_share = 0.0
	}
	
	entry = {
		goods = furniture
		
		weight = 2
		max\_supply\_share = 1.0
		min\_supply\_share = 0.0
	}

	entry = {
		goods = <good>
		
		weight = 2
		max\_supply\_share = 1.0
		min\_supply\_share = 0.0
	}
}

Needs can also define modifiers to obsession demand multipliers and prestige good demand increases. These are done at the need level, not at the goods level. For example:

popneed\_leisure = {
	default = services
	
	obsession\_demand\_min = 0.5 #Obsessions have this minimum share weight, overriding smaller defined minimums
	obsession\_demand\_mult = 2.0 #Obsessions multiply their demand weight multiplied by this
	prestige\_goods\_demand\_increase = 1.0 #Prestige goods add this to their demand weight, scaled by percentage of the market share

#### Creating a new need\[[edit](/index.php?title=Goods_modding&veaction=edit&section=10 "Edit section: Creating a new need") | [edit source](/index.php?title=Goods_modding&action=edit&section=10 "Edit section: Creating a new need")\]

Creating a completely new need, is much more complicated and requires a lot of footwork, but not that much harder.

First, a completely new need needs to be created in /common/pop\_needs/.

popneed\_<name> = {
	default = <good> 

	entry = {
		goods = <good>
	}
}

And following localization entry:

popneed\_<name>: "Digital Entertainment"

The default good is what substitutes orient themselves around. Usually the most basic, initial and cheapest good. E.g. even the `popneed_art` has `services` as a default.

Weight, and min and max are not needed if there is only a single good.

Then the `buy_package` must be modified in /common/buy\_packages/00\_buy\_packages.txt.

(After initial tests, it seems here is best to completely overwrite `00_buy_packages.txt`)

wealth\_1 = {
	political\_strength = 0.03
	goods = {
		popneed\_simple\_clothing = 23
		popneed\_basic\_food = 90
		popneed\_heating = 15
		popneed\_intoxicants = 23
		popneed\_<name> = <int>
	}
}
wealth\_2 = {
	political\_strength = 0.04
	goods = {
		popneed\_simple\_clothing = 27
		popneed\_basic\_food = 94
		popneed\_heating = 17
		popneed\_intoxicants = 27
		popneed\_<name> = <int>
	}
}
...
wealth\_99 = {
	political\_strength = 1500
	goods = {
		popneed\_heating = 26
		popneed\_services = 273303
		popneed\_intoxicants = 216
		popneed\_luxury\_drinks = 136652
		popneed\_free\_movement = 136652
		popneed\_communication = 136652
		popneed\_luxury\_food = 136652
		popneed\_luxury\_items = 546607
		popneed\_art = 341629
		popneed\_<name> = <int>
	}
}

The new need then needs to be added to **every** relevant wealth level. So, if this is a need that pops of between SoL 15 and 40 should have, then that means adding the entry to `wealth_15`, `wealth_16`, `wealth_17`, `wealth_18`, `wealth_18`...`wealth_39`, `wealth_40`.

The integer value decides on how much money must be spend on this good to satisfy the need by one "Normal" pop size. For more info, refer to [Needs#Formulas](/Needs#Formulas "Needs") Various people have already come up with various scripts and tools to help automate this process. One such tool would be [Vic3 Dev Utilities](https://github.com/Imperia-Development-Victoria-3/Victoria-3-dev-utilities)
