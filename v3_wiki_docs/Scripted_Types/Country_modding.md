From Victoria 3 Wiki

[Countries](/Countries "Countries") in Victoria 3 are defined by a small number of base characteristics, most of which are adjustable in-game by scripting or player action; however the base characteristics always remain as scripted.

## Country definition\[[edit](/index.php?title=Country_modding&veaction=edit&section=1 "Edit section: Country definition") | [edit source](/index.php?title=Country_modding&action=edit&section=1 "Edit section: Country definition")\]

Countries are defined in /common/country\_definitions/; each country definition has required and optional elements:

Country definition elements

Characteristic

Use

Example

Required?

TAG

Internal script ID, always three letters, creates the definition block

GER

![Yes](/images/thumb/7/77/Yes.png/24px-Yes.png "Yes")

color

Base map color: in RGB, hsv, or hsv360 colorspace

color = { 147 130 110 }

![Yes](/images/thumb/7/77/Yes.png/24px-Yes.png "Yes")

country\_type

Starting diplomatic type, defined in common/country\_types

country\_type = recognized

![Yes](/images/thumb/7/77/Yes.png/24px-Yes.png "Yes")

tier

Prestige tier, currently a hardcoded [list](/Rank#Prestige_sources "Rank")

tier = empire

![Yes](/images/thumb/7/77/Yes.png/24px-Yes.png "Yes")

cultures

Primary cultures, one or more

cultures = { north\_german south\_german }

![Yes](/images/thumb/7/77/Yes.png/24px-Yes.png "Yes")

State religion, if different from default religion of first primary culture

![No](/images/thumb/0/04/No.png/24px-No.png "No")

![Yes](/images/thumb/7/77/Yes.png/24px-Yes.png "Yes")

Overrides usual state naming mechanics for split states

is\_named\_from\_capital = yes

![No](/images/thumb/0/04/No.png/24px-No.png "No")

![No](/images/thumb/0/04/No.png/24px-No.png "No")

Sets a social hierarchy for use by this country

social\_hierarchy = british\_indian\_caste\_system

![No](/images/thumb/0/04/No.png/24px-No.png "No")

<order>\_unit\_color

Sets a consistent unit model color (in RGB); `primary, secondary, or tertiary`

primary\_unit\_color = { 20 20 120 }

![No](/images/thumb/0/04/No.png/24px-No.png "No")

A full definition typically appears similar to this example:

GER = {
	color = { 147 130 110 }
	
	country\_type = recognized

	tier = empire
	
	cultures = { north\_german south\_german }
	capital = STATE\_BRANDENBURG
}

More notes:

-   `color` is assumed as rgb unless set as hsv or hsv360:
    -   thus `color = { 147 130 110 }` is read as rgb (in 0-255 values)
    -   while `color = hsv{ 0.99 0.7 0.9 }` uses percentage HSV
    -   and `color = hsv360{ 20 80 80 }` uses 0-360 Hue and 0-100 Saturation and Value.
-   Characteristics which can be changed by script – such as type, cultures, and religion – are reset to the defined values if the country ceases to exist during the game and then later is released or reformed.

### Country formation\[[edit](/index.php?title=Country_modding&veaction=edit&section=2 "Edit section: Country formation") | [edit source](/index.php?title=Country_modding&action=edit&section=2 "Edit section: Country formation")\]

Country formations – i.e. [unifications](/Formable_countries "Formable countries") – are defined in /common/country\_formation/. Each formation must be based on an already existing country definition. Formations are defined on two axes: major versus minor, and cultural homelands versus defined list of states.

All formations require a list of states, either explicitly defined or with `use_culture_states = yes` which uses all states with a homeland of any of the country's primary cultures as its list of states.

Country formation elements

Characteristic

Use

Example

Notes

TAG

Internal script ID, creates the definition block

LAO

Must match already defined country

states

A defined list of states, one or more

states = { STATE\_LAOS }

Don't use along with `use_culture_states`

use\_culture\_states

All cultural homelands of the country's cultures are used

use\_culture\_states = yes

Don't use along with `states`

required\_states\_fraction

Percentage of states required for formation

required\_states\_fraction = 0.75

Defaults to 0.75 if omitted

ai\_will\_do

Conditions for the AI to decide to form this country

ai\_will\_do = { triggers }

Vanilla mainly uses `always = yes`

possible

Additional requirements for formation

possible = { triggers }

Vanilla mainly uses `has_technology_researched = (pan-)nationalism`

max\_num\_formation\_candidates

Overrides the default amount of formation candidates

max\_num\_formation\_candidates = 1

Default is 3

can\_be\_formation\_candidate

Additional requirements to be a candidate for a major formation

can\_be\_formation\_candidate = { triggers }

candidates must also fulfill the possible block

can\_be\_unification\_target

Additional requirements to be a valid target for unification plays

can\_be\_unification\_target = { triggers }

An example with a defined state list:

LAO = {
	states = {
		STATE\_LAOS
	}

	required\_states\_fraction = 1.0
	
	ai\_will\_do = { always = yes }
}

An example with `use_culture_states = yes`

UBD = {
	use\_culture\_states = yes

	required\_states\_fraction = 1
	
	ai\_will\_do = { always = yes }

	possible = {
		has\_technology\_researched = pan-nationalism
	}
}

Major formations are declared by adding `is_major_formation = yes`. Major formations also have two diplomatic plays `unification_play` and `leadership_play` which should match existing [diplomatic plays](/Diplomacy_modding "Diplomacy modding") with the wargoals of `unification` and `unification_leadership` respectively

An example of a major formation:

ITA = {
	use\_culture\_states = yes

	is\_major\_formation = yes

	unification\_play = dp\_unify\_italy
	leadership\_play = dp\_leadership\_italy

	required\_states\_fraction = 0.7

	ai\_will\_do = { has\_technology\_researched = nationalism }

	possible = {
		OR = {
			country\_has\_primary\_culture = cu:north\_italian
			country\_has\_primary\_culture = cu:south\_italian
		}
	}
	
	max\_num\_formation\_candidates = 3
	can\_be\_formation\_candidate = {
		country\_rank >= rank\_value:minor\_power
		any\_country = {
			filter = {
				OR = {
					country\_has\_primary\_culture = cu:north\_italian
					country\_has\_primary\_culture = cu:south\_italian
				}
			}
			has\_technology\_researched = nationalism
			percent = 1
		}
	}
}

Forming the country requires only the possible block, while the unification candidate mechanic requires both the possible block and the can\_be\_formation\_candidate block.

### Country creation\[[edit](/index.php?title=Country_modding&veaction=edit&section=3 "Edit section: Country creation") | [edit source](/index.php?title=Country_modding&action=edit&section=3 "Edit section: Country creation")\]

Country creations – i.e. [liberations](/Releasable_countries "Releasable countries") – are defined in /common/country\_creation/. Each creation must be based on an already existing country definition. Creations are defined by either cultural homelands, a defined list of states, or a defined list of provinces. Note that a country's defined capital is effectively always included in the list of required states or culture states, even if not explicitly added to the list or a cultural homeland.

Country creation elements

Characteristic

Use

Example

Notes

TAG

Internal script ID, creates the definition block

JAM

Must match already defined country

provinces

A defined list of provinces, one or more

provinces = { xC08061 x68BE66 }

Don't use along with `use_culture_states` or `states`  
The provinces do not need to belong to the same state

states

A defined list of states, one or more

states = { STATE\_JAMAICA }

Don't use along with `use_culture_states` or `provinces`

use\_culture\_states

All cultural homelands of the country's cultures are used

use\_culture\_states = yes

Don't use along with `states` or `provinces`

required\_num\_states

Number of states required for release

required\_num\_states = 2

Defaults to 0 (effectively 1) if omitted

ai\_will\_do

Conditions for the AI to decide to release this country

ai\_will\_do = { triggers }

Vanilla always uses `always = no`

possible

Additional requirements for release

possible = { triggers }

Vanilla mainly uses `has_technology_researched = (pan-)nationalism`

An example of a country release definition

PHI = {
	states = { 
		STATE\_MINDANAO
		STATE\_LUZON
		STATE\_VISAYAS
	}
	required\_num\_states = 2
	ai\_will\_do = { always = no }
}

## Localization\[[edit](/index.php?title=Country_modding&veaction=edit&section=4 "Edit section: Localization") | [edit source](/index.php?title=Country_modding&action=edit&section=4 "Edit section: Localization")\]

Countries automatically generate [localization](/Localization "Localization") keys based on their tags: TAG and TAG\_ADJ, which define the country's name and adjective.

Dynamic names can be defined in common/dynamic\_country\_names, with a `DEFAULT` block usable by any country and then TAG blocks specific to those tags

TAG = {
	dynamic\_country\_name = {
		name = string # This can be set to the default name by using TAG as the string
		adjective = string # This can be set to the default adjective by using TAG\_ADJ as the string

		is\_revolutionary = yes # default no, if yes then used for revolts only
        
		is\_main\_tag\_only = yes # default no, if yes then only the primary country for a definition can use this name (ie Poland, not dynamic revolt Poland)
        
		priority = 0 # default 0, if multiple names have valid triggers, higher priority is used. If same priority, first one in file is used
		
		# Scripted trigger, country-scope
		trigger = {
		}
	}	
}

## Map color\[[edit](/index.php?title=Country_modding&veaction=edit&section=5 "Edit section: Map color") | [edit source](/index.php?title=Country_modding&action=edit&section=5 "Edit section: Map color")\]

A country's default map color is defined as above, but dynamic colors can be scripted in common/dynamic\_country\_map\_colors. The first dynamic color which returns true is used, unless the [game rule](/Game_rule "Game rule") *Map Color for Subjects* on and the country is a subject.

kalmar\_union = { #This is just an arbitrary script name, should be unique for dynamic colors
	color = "kalmar\_orange" # a "named color" defined in common/named\_colors

	possible = { # Scripted trigger, country-scope
		exists = c:SCA
		THIS = c:SCA
		has\_law = law\_type:law\_monarchy
		ruler = {
			has\_culture = cu:danish
		}
	}
}

Named colors are defined in the same way as a country's default color, with a declared hsv360 or rgb color, except tied to a script name. Named colors can be used for dynamic map colors as well as flag colors.

## Flags\[[edit](/index.php?title=Country_modding&veaction=edit&section=6 "Edit section: Flags") | [edit source](/index.php?title=Country_modding&action=edit&section=6 "Edit section: Flags")\]

*Main article: [Flag modding](/Flag_modding "Flag modding")*

Countries have flags dynamically generated if they do not have a defined flag; otherwise they use a defined flag as scripted.

### Flag colors and unit model colors\[[edit](/index.php?title=Country_modding&veaction=edit&section=7 "Edit section: Flag colors and unit model colors") | [edit source](/index.php?title=Country_modding&action=edit&section=7 "Edit section: Flag colors and unit model colors")\]

Unit models in game draw their colors from either the country's defined unit colors or from the currently used coat of arms' colors.

Unit model colors can be defined in a country's definition as:

	primary\_unit\_color = { 20 20 120 }
	secondary\_unit\_color  = { 150 190 210 }
	tertiary\_unit\_color = { 5 5 90 }

Otherwise, the first three base/pattern colors defined for a coat of arms determine the unit model colors, even if those colors don't appear on the flag. Colors defined for emblems are never considered.

## Country history\[[edit](/index.php?title=Country_modding&veaction=edit&section=8 "Edit section: Country history") | [edit source](/index.php?title=Country_modding&action=edit&section=8 "Edit section: Country history")\]

*See also: [History modding](/History_modding "History modding")*

/common/history/countries/ contains the starting political set up for countries that exist at game start. These are effect blocks, with several effects set up as scripted effects to unify common sets of laws and technologies.

One of those effect blocks is `effect_starting_politics_conservative = yes` which gives the following laws:

Monarchy

Interventionism

Censorship

Oligarchy

Mercantilism

No Workers' right

National Supremacy

Per-Capita Taxation

Child Labor Allowed

State Religion

Tenant farmers

Legal Guardianship

Appointed Bureaucrats

No Colonial Affairs

No social security

Professional Army

Local Police Force

Migration Controls

No Home Affairs

Religious Schools

Slavery Banned

No Health System

Combination Acts

If no laws are defined for a group, the "default" law in each group is active at game start. These are generally the first law scripted in the law files, unless a country does not meet the requirements for that law.

**Technologies**

You can unlock an individual technology for a country, such as Sericulture, by writing `add_technology_researched = sericulture` in its country file. A technology tier is a group of technologies you can assign a country in a single line like `effect_starting_technology_tier_6_tech = yes` for ease of use. There are 6 tiers, and tier 5 contains tier 6, tier 4 contains tier 5, tier 3 contains tier 4, and so on. The following tables show the difference in technologies between consecutive tiers.
