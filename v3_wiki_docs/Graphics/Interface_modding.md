## Templates and types\[[edit](/index.php?title=Interface_modding&veaction=edit&section=1 "Edit section: Templates and types") | [edit source](/index.php?title=Interface_modding&action=edit&section=1 "Edit section: Templates and types")\]

### Templates\[[edit](/index.php?title=Interface_modding&veaction=edit&section=2 "Edit section: Templates") | [edit source](/index.php?title=Interface_modding&action=edit&section=2 "Edit section: Templates")\]

Templates are simply containers for properties. So `using = template_name` simply adds all properties (like `size` etc.) and widgets/containers, that are in the template block, to the current widget/container.

**Defining a Template**

Create a new `.gui` file in the `game/gui` folder (subfolders are also supported):

template example\_template {
    container = {
        # Some container
    }

    # Properties
    size = { 100 100 }
}

### Types\[[edit](/index.php?title=Interface_modding&veaction=edit&section=3 "Edit section: Types") | [edit source](/index.php?title=Interface_modding&action=edit&section=3 "Edit section: Types")\]

Types are widget/container in itself that allow reuse and overwriting properties in it.

**Defining a Type**

Create a new `.gui` file in the `game/gui` folder (subfolders are also supported):

types my\_types {
    # Base type
    type example\_base\_type = widget {
        # Anything you want

        # Defining a set of overwritable properties or widgets/containers
        block "test\_block" {
            size = { 100 100 }
        }
    }

    # Extended type
    type extended\_example\_type = example\_base\_type {
        # Anything you define here will be added at the bottom of the base type

        # Overwriting a predefined block
        blockoverride "test\_block" {
            size = { 200 200 }
        }
    }
}

### Using a type\[[edit](/index.php?title=Interface_modding&veaction=edit&section=4 "Edit section: Using a type") | [edit source](/index.php?title=Interface_modding&action=edit&section=4 "Edit section: Using a type")\]

Types can be referred anywhere even in other types:

widget = {
    # Using the type as is
    example\_base\_type = {}

    # Overwriting a block in the type
    example\_base\_type = {
        # Overwriting a predefined block
        blockoverride "test\_block" {
            size = { 200 200 }
        }
    }

    # Extending the type
    example\_base\_type = {
        widget = {
            # This widget will be added at the bottom of the existing content
        }
    }
}

## Creating custom panels\[[edit](/index.php?title=Interface_modding&veaction=edit&section=5 "Edit section: Creating custom panels") | [edit source](/index.php?title=Interface_modding&action=edit&section=5 "Edit section: Creating custom panels")\]

### Setting up the windows\[[edit](/index.php?title=Interface_modding&veaction=edit&section=6 "Edit section: Setting up the windows") | [edit source](/index.php?title=Interface_modding&action=edit&section=6 "Edit section: Setting up the windows")\]

Create a type for the window you want to implement.

This is an example for a side panel:

type example\_side\_panel = default\_block\_window {
    # Important to make sure the window does not overlay other base game stuff
    layer = layer\_ingame\_menu
    
    # Decide visibility i.e. when should your window be shown
    # Best practice is using the GUI variable system
    visible = "\[GetVariableSystem.HasValue('com\_open\_window', 'example\_side\_panel')\]"

    # Adding this to the show state is important otherwise your window may be overlayed by
    # base game windows or not close base game windows correctly
    # See the base game for how to set sound effects and other stuff here
    blockoverride "animation\_state\_block" {
        state = {
            name = \_show
            # Close other open panels before showing this one
            on\_finish = "\[InformationPanelBar.ClosePanel\]"
            on\_finish = "\[MapListPanelManager.CloseCurrentPanel\]"
        }
    }

    # Your window implementation
    # See base game panels for examples on how to set up
    # tabs, fixed bottoms and other stuff
}

For full screen panels the above points still apply but for your window to work correctly you also need to hide some GUI components. To do that you either overwrite the base game logic or use the [Community Mod Framework](https://github.com/Victoria-3-Modding-Co-op/Community-Mod-Framework). It has guides on how to set up the hiding of the GUI elements. The main difference for full screen panels is that they are based on another base type:

type example\_full\_screen\_panel = fullscreen\_block\_window {
    # Same as side panel
}

### Adding your panels to the game\[[edit](/index.php?title=Interface_modding&veaction=edit&section=7 "Edit section: Adding your panels to the game") | [edit source](/index.php?title=Interface_modding&action=edit&section=7 "Edit section: Adding your panels to the game")\]

To add your panels to the game you will need to create a scripted widget.

First create a new GUI file and set it up like this:

widget = {
    name = example\_panels
    layer = layer\_ingame\_menu
    size = { 100% 100% }

    # Full screen panels go here
    # Refer to them like this:
    example\_full\_screen\_panel = {}

    vbox = {
        parentanchor = top|left
        layoutpolicy\_horizontal = expanding
        layoutpolicy\_vertical = expanding
        margin\_top = 85 #margin topbar

        widget = {
            layoutpolicy\_horizontal = expanding
            layoutpolicy\_vertical = expanding

            hbox = {
                layoutpolicy\_horizontal = expanding
                layoutpolicy\_vertical = expanding

                # Side panels go here
                # Refer to them like this:
                example\_side\_panel = {}

                expand = {}
            }
        }
    }
}

Next you need to register your scripted widget. To do that create a new TXT file in the `game/gui/scripted_widgets/` folder and add a line like this

gui/name\_of\_the\_file\_with\_widget.gui = example\_panels
