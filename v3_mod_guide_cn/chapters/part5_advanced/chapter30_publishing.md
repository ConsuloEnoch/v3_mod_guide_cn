## 概念讲解：发布是什么？

### 比喻：举办展览

想象你是一位艺术家，完成了作品准备展出：
- **打包Mod** = 精心装裱画作
- **上传平台** = 在画廊租展位
- **版本管理** = 给每个作品编号
- **更新日志** = 展览说明卡
- **社区推广** = 发邀请函

发布就是让你的作品被更多人看到和使用的过程。

### 为什么要发布？

1. **分享创意**：让其他玩家体验你的作品
2. **获得反馈**：社区反馈帮助改进
3. **建立声誉**：成为知名Mod作者
4. **回馈社区**：为游戏生态做贡献

## 30.1 Mod打包

### 30.1.1 打包前检查清单

**文件完整性**：
- [ ] 所有必要文件已包含
- [ ] 没有遗漏任何资源（图片、本地化）
- [ ] 没有包含测试文件或临时文件
- [ ] 代码已经过测试

**信息完整性**：
- [ ] metadata.json已正确填写
- [ ] Mod有清晰的名字和描述
- [ ] 包含版本号
- [ ] 指定了游戏版本兼容性

**质量检查**：
- [ ] 没有明显的bug
- [ ] 本地化完整
- [ ] 游戏性能良好
- [ ] 与其他常用Mod兼容

### 30.1.2 文件组织

**正确的Mod结构**：

```pdx
my_mod/
├── .metadata/               # Mod元数据
│   └── metadata.json
├── common/                  # 游戏数据
├── events/                  # 事件
├── decisions/               # 决策
├── journal_entries/         # 日志条目
├── localization/            # 本地化
├── gfx/                     # 图形资源
├── gui/                     # 界面
└── README.md                # 说明文件（可选）

```

**应该移除的文件**：
- ❌ 备份文件（.bak）
- ❌ 临时文件（.tmp）
- ❌ 版本控制文件（.git）
- ❌ 编辑器配置文件
- ❌ 未使用的测试文件
- ❌ 调试代码和注释掉的代码

### 30.1.3 创建发布包

**方法一：手动打包**

1. 复制Mod文件夹到新位置
2. 删除不必要的文件
3. 压缩为.zip或.rar格式
4. 命名为：`my_mod_v1.0.zip`

**方法二：使用工具**

一些Mod管理工具可以帮助打包：
- Paradox Mod Manager
- Vortex（Nexus Mods）

### 30.1.4 metadata.json配置

```json
{
  "name": "江南共和国",
  "id": "jiangnan_republic_mod",
  "version": "1.0.0",
  "supported_game_version": "1.5.*",
  "short_description": "添加江南共和国和洋务运动内容",
  "tags": ["National Focus", "Events", "Decisions"],
  "relationships": [],
  "game_custom_data": {
    "multiplayer_synchronized": true
  }
}

```

**参数说明**：

| 参数                   | 说明         | 示例                    |
| ---------------------- | ------------ | ----------------------- |
| name                   | Mod显示名称  | "江南共和国"            |
| id                     | 唯一标识符   | "jiangnan_republic_mod" |
| version                | 版本号       | "1.0.0"                 |
| supported_game_version | 兼容游戏版本 | "1.5.*"                 |
| short_description      | 简短描述     | "添加江南共和国..."     |
| tags                   | 分类标签     | ["Events", "Decisions"] |
| relationships          | 依赖关系     | 见下文                  |

**版本号规范**（语义化版本）：
- `主版本.次版本.修订号`
- 例如：`1.2.3`
  - 1：重大更新（可能不兼容）
  - 2：新功能
  - 3：Bug修复

**依赖关系示例**：

```json
{
  "relationships": [
    {
      "id": "base_game",
      "type": "required"
    },
    {
      "id": "another_mod",
      "type": "optional"
    },
    {
      "id": "conflicting_mod",
      "type": "incompatible"
    }
  ]
}

```

## 30.2 上传到Paradox Mods

### 30.2.1 准备工作

**需要准备**：
1. Paradox账号
2. Mod文件（已打包）
3. 封面图片（推荐尺寸：1920x1080）
4. 详细描述
5. 截图（3-5张）

### 30.2.2 上传步骤

**通过启动器上传**：

1. 打开Paradox启动器
2. 点击"Mods"标签
3. 点击"上传Mod"
4. 选择你的Mod
5. 填写信息：
   - 标题
   - 描述
   - 标签
   - 预览图
6. 点击"上传"

**通过网站上传**：

1. 访问：https://mods.paradoxplaza.com/
2. 登录Paradox账号
3. 点击"Upload Mod"
4. 选择游戏（Victoria 3）
5. 上传文件并填写信息

### 30.2.3 撰写描述

**描述结构**：

```markdown
# 标题

## 简介
简要介绍Mod的内容和特色。

## 主要功能
- 功能1：说明
- 功能2：说明
- 功能3：说明

## 安装方法
1. 订阅Mod
2. 在启动器中启用
3. 开始游戏

## 兼容性
- 与原版兼容
- 与以下Mod兼容：...
- 不兼容：...

## 更新日志
### v1.1.0
- 新增：...
- 修复：...

### v1.0.0
- 初始发布

## 反馈
如有问题，请在评论区留言或联系：
- Steam：...
- Discord：...
- Email：...

## 致谢
感谢以下人员/资源：
- ...

```

**描述技巧**：
- 使用清晰的标题和段落
- 添加截图展示效果
- 列出具体功能点
- 说明兼容性
- 提供联系方式

### 30.2.4 添加截图

**截图要求**：
- 格式：JPG或PNG
- 尺寸：推荐1920x1080
- 数量：3-5张
- 内容：展示Mod的主要功能

**截图建议**：
1. **封面图**：最具代表性的画面
2. **功能展示**：新内容的效果
3. **事件截图**：剧情或事件界面
4. **决策界面**：新决策的效果
5. **地图变化**：如果有地理修改

## 30.3 版本管理

### 30.3.1 版本控制策略

**语义化版本规范**：

| 版本类型 | 格式       | 示例       | 何时使用               |
| -------- | ---------- | ---------- | ---------------------- |
| 主版本   | X.0.0      | 2.0.0      | 重大更新，可能破坏存档 |
| 次版本   | x.X.0      | 1.1.0      | 新增功能，向后兼容     |
| 修订号   | x.x.X      | 1.0.1      | Bug修复，向后兼容      |
| 预览版   | x.x.x-beta | 1.1.0-beta | 测试版本               |

### 30.3.2 版本更新流程

```pdx
1. 修改代码
   ↓ 添加新功能或修复bug
2. 测试验证
   ↓ 确保正常工作
3. 更新版本号
   ↓ 修改metadata.json
4. 撰写更新日志
   ↓ 记录改动内容
5. 重新打包
   ↓ 创建新版本文件
6. 上传更新
   ↓ 上传到Mod平台
7. 通知用户
   ↓ 发布更新说明

```

### 30.3.3 存档兼容性

**重大更新（X.0.0）**：
- 通常会破坏存档兼容性
- 需要玩家开始新游戏
- 在描述中明确说明

**功能更新（x.X.0）**：
- 一般保持存档兼容
- 新增内容在存档中也能体验
- 建议玩家开始新游戏以获得最佳体验

**修复更新（x.x.X）**：
- 总是保持存档兼容
- 可以安全更新
- 修复bug不影响现有游戏

### 30.3.4 更新日志规范

**格式**：

```markdown
## 版本 1.2.0 - 2026年4月1日

### 新增
- 添加5个新事件
- 新增江南制造局建筑
- 添加洋务运动日志条目

### 改进
- 优化事件触发逻辑
- 改进本地化文本
- 调整平衡性

### 修复
- 修复事件不触发的问题
- 修复本地化显示错误
- 修复江南旗帜不显示的问题

### 平衡性调整
- 降低洋务运动成本
- 增加江南初始人口

```

**建议**：
- 每个版本都有更新日志
- 分类列出改动（新增、修复、改进）
- 标注重大变更
- 感谢贡献者

## 30.5 维护与更新

### 30.5.1 定期维护

**维护任务**：
- 修复报告的Bug
- 更新游戏版本兼容性
- 改进平衡性
- 添加新内容
- 优化性能

**更新频率建议**：
- Bug修复：尽快
- 小更新：每月
- 大更新：每季度

### 30.5.2 游戏版本更新

当游戏更新时：

1. **测试兼容性**：
   - 在最新游戏版本测试
   - 检查是否有新错误

2. **更新metadata.json**：

   ```json
   {
     "supported_game_version": "1.6.*"
   }

   ```

3. **适配新功能**：
   - 使用新增的游戏功能
   - 调整受影响的代码

4. **发布更新**：
   - 更新版本号
   - 撰写更新日志
   - 上传新版本

### 30.5.3 长期支持

**LTS（长期支持）策略**：
- 维护稳定版本
- 只为重大Bug发布修复
- 新功能在开发分支进行

**版本分支**：

```pdx
主分支（稳定版）
  ↓
开发分支（新功能）
  ↓
修复分支（紧急修复）

```

## 常见问题

**Q1：上传后Mod不显示？**

检查：
1. metadata.json是否正确
2. 是否点击了"发布"
3. 平台审核可能需要时间
4. 检查邮箱是否有审核通知

**Q2：如何更新已发布的Mod？**

步骤：
1. 修改代码
2. 更新metadata.json中的版本号
3. 重新打包
4. 在启动器中选择"更新Mod"
5. 上传新版本

**Q3：可以设置付费Mod吗？**

Paradox Mods目前不支持直接付费，但可以通过：
- Patreon接受捐赠
- Ko-fi接受支持
- 自愿捐赠链接

**Q4：如何处理负面评价？**

建议：
1. 保持冷静和专业
2. 理解用户痛点
3. 解释设计决策
4. 承诺改进
5. 不要争论

**Q5：Mod被盗用怎么办？**

步骤：
1. 联系平台举报
2. 提供原创证明
3. 在社区发声
4. 必要时寻求法律帮助
